# OctoAcme Project Management Docs

Welcome to the OctoAcme project management documentation. This README serves as the entry point for all core process docs and summarizes how project work is managed at OctoAcme. Whether you are a new team member getting up to speed or a seasoned contributor looking for a reference, this documentation suite is designed to help you navigate our processes quickly and confidently.

## Project Management Approach

OctoAcme projects follow a structured lifecycle: **Initiation → Planning → Execution & Tracking → Release & Deployment → Retrospective & Continuous Improvement**. Each phase is supported by standard templates, checklists, and clear ownership to ensure quality and repeatability across all teams. Core principles guiding every project include customer-centricity, iterative delivery, data-informed decision-making, and psychological safety.

Three key roles drive project delivery: the **Project Manager (PM)** coordinates schedules, risks, and communications; the **Product Manager (PdM)** defines outcomes, prioritizes the backlog, and measures success; and **Developers** implement and validate features against acceptance criteria. QA, stakeholders, and other contributors participate at defined touchpoints throughout the lifecycle. Persona definitions and responsibilities for each role are captured in the [Roles & Personas](octoacme-roles-and-personas.md) document.

Communication is intentional and regular. Teams hold twice-weekly standups, weekly PM–PdM syncs, and monthly stakeholder updates, supplemented by ad-hoc escalation paths when needed. Risks are tracked in a shared Risk Register and reviewed at every weekly sync. When incidents or blockers arise, a defined escalation path — team → PM → Product Lead → Sponsor — ensures issues are resolved at the right level. After each sprint, release, or milestone, a structured retrospective captures learnings and converts them into backlog action items, driving a culture of continuous improvement.
